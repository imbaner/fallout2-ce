## Подтверждённая причина

Журнал аварий непосредственно с телефона содержит SIGABRT и сообщение:
`artLock(const FrmId& ...) called with path based FrmId which is not supported!`
(`src/art.cc:541`). Стек: `mainMenuWindowUnhide` → затухание палитры →
`renderPresent` → `muiRender` → `muiPictureTexture` → `artLock`.

`mui_main_menu.cc` правильно запрашивал `InterfaceFrmId("HR_MAINMENU.FRM")`.
Но `muiPictureTexture` использовал старый `artLock`, работающий только с
числовыми FID. Поэтому assert срабатывал при первом кадре меню. Ролики
предшествуют этому месту и не являются причиной вылета. Отключать assert
или возвращать обрезанный старый фон для исправления не требовалось.

Обнаружена и связанная ошибка кэша: ключом служил только `frmId.fid()`.
У именованных ресурсов FID равен -1, поэтому разные пути могли получить
одну текстуру. Простая замена загрузчика без исправления ключа оставила бы
эту ошибку, включая неверный результат для отсутствующего файла.

## Исправление

В `src/mui_draw.cc`, функция `muiPictureTexture`:

- Используется существующий `FrmImage::lock`, поддерживающий числовые FID
  и именованные ресурсы. Данные и размеры берутся из `FrmImage`.
- Владение ресурсом управляется временем жизни `FrmImage`; освобождение
  происходит и на ранних выходах.
- Ключ кэша содержит FID, тип объекта и собственную копию строки пути.
  Числовые ресурсы и разные именованные изображения не смешиваются.
- При неудаче размеры обнуляются, возвращается `nullptr`; существующий
  fallback главного меню остаётся рабочим.
- Сохранены обновление текстуры при смене палитры, линейная фильтрация,
  нативные тач-виджеты и GPU-отрисовка. Геометрия меню и исходные игровые
  файлы не изменялись. Полный HR-фон по-прежнему прижат справа без искажения.
